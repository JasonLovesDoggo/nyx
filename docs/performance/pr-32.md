# PR #32: Shiki output optimization

Baseline: PR head `570bf4f`, which already uses style-to-class, an `esnext` target,
Lightning CSS for extracted CSS, and no modulepreload polyfill. These numbers
measure the **additional** optimization, not the original inline-style PR.

## Changes

```diff
 Markdown → Shiki → mdsvex → Svelte
- each code block: its own repeated token stylesheet
+ each document: one deduplicated, Lightning CSS-minified token stylesheet
- copy button: base64 duplicate of the complete source
+ copy button: read pre > code textContent, retaining clipboard fallback
```

Collection is local to each document. It does not use global build state that
could leak styles across pages or lose styles during HMR/concurrent compilation.
Generated CSS keeps literal braces and escapes template-literal delimiters.

## Build output

Sizes are exact bytes. Client totals sum **all** emitted route chunks, excluding
maps, fonts, and images; they are not the initial download for a single page.
Gzip/Brotli columns sum each file compressed separately. Server chunks are build
artifacts, not browser downloads. No runtime-speed or Lighthouse claim is made.

## Verification

- `bun run build`: succeeds.
- `bun run check`: zero errors/warnings.
- `node --test scripts/shiki-styles.test.js scripts/codeblocks.test.js`: six passing tests.
- Changed files pass Prettier and ESLint.
- Browser snapshots of all 50 tutorial code blocks before/after: identical source
  text, exact copied text, and computed token colors/backgrounds/font styles in
  all four Catppuccin palettes.
- Unit tests exercise Unicode, indentation, blank lines, HTML/template-literal
  characters, denied clipboard permissions, textarea cleanup, and per-document
  CSS isolation.

Full-repository lint is **not clean on this older PR base**: untouched files still
have the unused `path`, built-in `URLSearchParams`, and layout parser errors fixed
by PR #43 on main. Prettier also flags the untouched layout. This optimization
leaves those unrelated files unchanged. The older Tailwind dependency also emits
the Node 26 deprecation warning already fixed on main.

## Reproduce build-size measurements

```sh
bun install --frozen-lockfile
bun run build
node scripts/measure-build.mjs
```

For an A/B comparison, run the same script after clean builds of `570bf4f` and the
optimized commit, using each commit's lockfile and the same runtime.
