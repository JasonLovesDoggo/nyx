# JetBrains Mono subsets

The four WOFF2 files and `fonts.css` are generated by hand, not by the site
build. They come from the two `@fontsource/jetbrains-mono` 5.2.8 Latin normal
faces in the lockfile. The original OFL license is included as `OFL.txt`; its
copyright notice declares no Reserved Font Name. The CSS family and system
fallback remain the same as before.

To regenerate after updating the font package or changing font coverage, CSS
font features, or preloads:

```sh
bun install --frozen-lockfile
python3 -m venv /tmp/nyx-fonts
/tmp/nyx-fonts/bin/pip install 'fonttools[woff]==4.60.2' 'brotli==1.2.1' 'zopfli==0.4.3'
/tmp/nyx-fonts/bin/python scripts/subset-fonts.py
```

Commit the four WOFF2 files, two original WOFF fallbacks, license, and `fonts.css`. Review their actual cmap and the
site's font usage after changing the inputs; update the preloads if file names
change. The core includes ASCII, common punctuation and the global copyright
symbol. The extended face contains every other character in the original
Latin face. The ranges are generated from the resulting cmap and do not
advertise glyphs that aren't there. There is no intermediary fallback face.
The original 27,496-byte and 28,208-byte WOFF files remain as fallbacks for
browsers without WOFF2 support; those browsers do not receive the WOFF2 savings.

This deliberately preserves the original Latin face's full character coverage
and hinting. Most Latin Extended-A characters were absent before and still use
system fallback; adding them would alter rendering. CJK similarly uses system
fallback. Dynamic content can contain characters outside the repository, so
preserving the original coverage avoids changing its fallback behavior. The
original fonts are static 400 and 700, not variable. The browser matches other
weights to these faces and synthesizes italic as before. Only the unused `frac`
feature was removed; `calt`, `ccmp`, `locl` and `mark` are retained where
present. Hint removal changed glyph pixels in the tested browser, and did not
reduce total WOFF2 size in the tested build: it was 42,920 bytes versus 42,872
with hinting, while the two core files were 32,580 versus 32,564 bytes.

## Measurement (2026-10-29)

The baseline is commit `be85a42` with Fontsource 5.2.8. The source WOFF2s are
21,168 and 21,908 bytes (400 and 700), 394 glyphs and 229 mapped characters
each, with no variable axes. Both contain `prep` and `gasp` tables; GSUB has
`calt`, `ccmp`, `frac`, `locl`, and GPOS has `mark`. There were no font
preloads. `syntax.css` disables contextual ligatures for code and requests
tabular numbers. `SlabTitle` uses weight 900 in JetBrains Mono and a system
serif for its italic words at weights 300, 400, or 500. No font-feature-settings
or automatic hyphenation was found in the site's source CSS. U+2010 was not
present in the original Latin font, so fallback for it is unchanged.
Scanning source and content text found these non-ASCII characters covered by
the original face: ©, ·, –, —, •, …, and ↓. Characters outside that face
include nonbreaking hyphen, →, emoji and variation selectors. Runtime content
is not bounded by that scan; the original cmap is therefore retained in full.
The generated core/extended files have 252/160 glyphs and 105/124 mapped
characters respectively at each weight. WOFF2 and WOFF sizes are file bytes.
The 400 WOFF2 becomes 15,984 bytes core plus 5,120 extended; the 700 WOFF2
becomes 16,580 bytes core plus 5,188 extended. Both parts together total
42,872 bytes versus 43,076 bytes originally; splitting helps when extended
characters aren't needed.

In the browser, all 38 current page routes requested both original WOFF2s:
43,076 font file bytes per cold page. The candidate preloads both core faces
(15,984 + 16,580 = 32,564 bytes) on each route. All routes requested only those
two files except `/tutorials/sorting-java`, which additionally requested the
5,120-byte 400 extended face (37,684 bytes). These are font file sizes, not
measured end-to-end page load times or HTTP transfer totals. Browser caching,
dynamic content, and later interactions can change the files requested.

At 1280×800 in the local Chromium preview, same-DOM baseline font overrides
versus the subset faces produced zero changed pixels on the home page, About
page with added accented, combining, CJK, bold and italic text, a scrolled
FastAPI code block, and the recursion tutorial. Fonts were awaited and images,
canvas and animations hidden to limit unrelated noise. This is a sample, not a
proof for all browsers, sizes, or content. An independent tutorial navigation
had different randomly colored tags; same-DOM comparison removed that content
variation. A direct canvas comparison with hinting removed differed at all
sizes tested (12–32px). To repeat visual validation, compare the two faces on
the same content and browser after `document.fonts.ready`, including bold
italic, combining marks, code ligatures and system-fallback characters.
